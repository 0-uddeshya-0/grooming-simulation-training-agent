# SECURITY / privacy / safeguards
**Privacy**: all inference and storage local; server binds 127.0.0.1; no telemetry or runtime network calls. Pseudonymous participant IDs only. SQLite in `data/` (git-ignored, `journal_mode=DELETE` so no WAL files). Deletion: `DELETE /api/participant/{pid}` removes rows and VACUUMs. Use full-disk encryption; delete backups/exports separately. Free text may contain special-category data (see ETHICS_NOTES).
**Safeguards (code, not a model)**: constants in `backend/constants.py` (config can only tighten); persona validator (age >= 19, no minor terms, length-limited fields, unknown keys rejected); output filter (minor references incl. numeric ages and obfuscation, explicit terms, image solicitation, meta/think leakage) with regenerate-then-end; user-side minor and distress rules end the session with the support screen; STOP is a whole-message match and a button; server-side 45-min per-conversation clock from a persisted start time, enforced by a background sweeper and on every request (no client needed); atomic `ended` flag checked before any reply is stored; limit-push counter.
**Known limits**: keyword filters can miss novel phrasing; false positives are accepted (fail closed). Distress detection is lexical, so the researcher must be present or reachable. The DELETE endpoint is unauthenticated on localhost (researcher-operated machine). Tags are intended exposure.
**Misuse**: persona files are researcher-side; no authoring UI; no endpoint returns prompts. The repo is currently public by the researcher's decision; the director rules and persona prompt are research-description level only.
