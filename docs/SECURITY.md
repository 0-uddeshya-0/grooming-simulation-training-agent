# SECURITY / privacy / safeguards
**Privacy**: all inference and storage local; server binds 127.0.0.1; no telemetry or runtime network calls. Pseudonymous participant IDs only. SQLite in `data/` (git-ignored, `journal_mode=DELETE` so no WAL files). Deletion (researcher side): viewer button or `scripts/delete_participant.py` removes rows and VACUUMs; the participant app has no delete endpoint. The app only accepts localhost Host headers. Use full-disk encryption; delete backups/exports separately. Free text may contain special-category data (see ETHICS_NOTES).
**Safeguards (code, not a model)**: constants in `backend/constants.py` (config can only tighten); persona validator (age >= 19, no minor terms, length-limited fields, unknown keys rejected); output filter implementing the ethics-board ceiling (minor/youthful references incl. numeric ages and obfuscation, explicit terms, image/video solicitation, sexual role-play, self-harm encouragement, threats/pressure/secrecy demands, money, identifying data requests, in-person meeting proposals, meta/think leakage) with regenerate-then-end; blocked text is logged for the researcher; `CEILING_ENFORCED` is a code constant (on); user-side minor and distress rules end the session with the support screen; STOP is a whole-message match and a button; server-side 45-min per-conversation clock from a persisted start time, enforced by a background sweeper and on every request (no client needed); atomic `ended` flag checked before any reply is stored; limit-push counter.
**Known limits**: keyword filters can miss novel phrasing; false positives are accepted (fail closed). Distress detection is lexical, so the researcher must be present or reachable. The DELETE endpoint is unauthenticated on localhost (researcher-operated machine). Tags are intended exposure.
**Misuse**: persona files are researcher-side; no authoring UI; no endpoint returns prompts. The repo is currently public by the researcher's decision; the director rules and persona prompt are research-description level only.

**Researcher viewer**: separate process/port (8001), 127.0.0.1 only, random per-start token (cookie/header), UI file lives outside `frontend/` so the participant app cannot serve it, no prompts or persona files exposed. The participant app has no deletion endpoint; deletion is by email to the researcher, then viewer or `scripts/delete_participant.py`.
**Known gaps**: keyword filters can miss novel phrasing and also block benign text (fail closed); the viewer token is shown in the researcher's terminal only; the DB is plaintext on disk (use full-disk encryption).
**Review-driven hardening (D-030)**: English-only guard (German replies rejected; German distress/STOP words recognised as a safety net); cue-based age patterns incl. number words; hidden-word detection ('m i n o r', 'm1n0r') without whole-string false positives; suggestive emoji, asterisk actions, meeting/where-do-you-live/secrecy patterns; rule-specific correction notes on regeneration and pre-checked neutral fallback lines (max 2) before a session is ended; no raw participant text in model prompts (disclosure categories only); per-session double-submit guard (409); client disconnects do not end sessions; UTF-8 file I/O (Windows).
**Relaxed ceiling and no-abrupt-ending changes (D-031, D-033)**: meeting/location/clothing/secrecy/insistence are allowed; threats/blackmail, money, exact identifiers, explicit content, images, minors, self-harm remain blocked in code. A filter hit never ends the chat (correction -> deflection -> persona line). Remaining hard stops: Stop/`STOP`, 45-min limit (with 90 s grace for a reply in flight), user states age < 18 (the persona never continues with a self-declared minor). Distress words pause with support (config `safeguards.distress_mode: end` is stricter and can be set for real participants).
