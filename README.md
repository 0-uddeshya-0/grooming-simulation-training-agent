# Manipulation-Simulation Training Agent (thesis artefact)

A chat-based training agent that simulates a persuasive online manipulator so adult participants experience personalised manipulation in a controlled setting; a debrief then explains which of six strategies they were exposed to (identity manipulation, rapport-building, risk assessment, enticement, relationship-building, sexualisation onset), plus offender-type and register positions. The app and all data stay on the researcher's computer (no telemetry); only the chat text is sent to the model service (Hyperbolic by default, or a local model).

> **Ethics notice.** Adult (18+) participants only. This is a **deception study**: it requires ethics approval, informed consent, a full debrief, and a researcher present or reachable. The persona is always an adult and never produces explicit sexual content (see *Ethics ceiling* below). A Stop button is always visible. **Do not use outside approved research.**

## Requirements
Python 3.10+ and internet. **No local compute is needed**: replies are generated by a cloud model on Hyperbolic (default, https://api.hyperbolic.xyz/v1). A local model (llama.cpp + GGUF, 16 GB RAM) is still supported, see the end of this section.

## Setup and run (Hyperbolic, default)
**Windows (PowerShell)** (PowerShell blocks scripts by default, so use this form):
```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1
copy .env.example .env          # then edit .env: HYPERBOLIC_API_KEY=your-key
.venv\Scripts\python scripts\check_model.py
powershell -ExecutionPolicy Bypass -File scripts\run.ps1
```
**Linux / macOS**:
```bash
scripts/setup.sh && cp .env.example .env     # edit .env, then:
.venv/bin/python scripts/check_model.py && scripts/run.sh
```
`.env` is git-ignored; the key is never stored in `config/` or the repo. `check_model.py` makes one tiny request per model and prints the base URL, the exact model ID sent in the JSON body, the HTTP status and the provider's answer. `run` checks the key, helplines age and contact details, starts the app and opens http://localhost:8000.

**Model** (`config/app.yaml` -> `model.hyperbolic`): base URL `https://api.hyperbolic.xyz/v1`; primary `meta-llama/Llama-3.3-70B-Instruct`, backup `meta-llama/Llama-3.1-70B-Instruct` (used only if the primary is unavailable or stays busy). IDs are sent verbatim. A human-simulation system block (`system_prefix`) is added to every request and merged into the first system message. These are standard (not abliterated) Llama weights, so the model may refuse or soften some persona behaviour; the persona's hard limits are enforced in code (`backend/filters.py`) and refusals are caught and regenerated, so the model is never trusted for either side.

**Privacy**: with a cloud provider, participants' chat messages leave the computer (to Hyperbolic). The consent page states this automatically. See `docs/ETHICS_NOTES.md`.

### Alternative: local model
Set `model.provider: local` in `config/app.yaml`, then run `scripts/setup` (downloads llama.cpp), `python scripts/download_model.py` (Hugging Face GGUF, checksum-verified) and `scripts/run`; add `--cpu` if the GPU/Vulkan start fails. Benchmark with `python scripts/benchmark.py --label "<model quant>"`.

## Running a session
Give the participant an ID (e.g. `P001`), open the app, they consent and confirm 18+, pick a persona, chat. **Stop** (or typing `STOP`) ends a chat at once and shows the debrief. Each persona conversation can last up to 45 minutes (enforced by the server; no timer on screen). One researcher must be present or reachable.

**Researcher log viewer** (separate terminal; never shown to participants): `powershell -ExecutionPolicy Bypass -File scripts\researcher.ps1` (or `scripts/researcher.sh`) prints a private URL with a one-time token. It lists sessions, transcripts with the intended strategy tag per attacker message, blocked outputs and distress events, a tag-validity check (mark whether each tag matches the text), CSV export, and per-participant deletion.

## Data and deletion
`data/study.db` (SQLite, git-ignored, pseudonymous IDs only, no WAL files). Participants are told to email the researcher with their ID to have data deleted: use the viewer's delete button or `.venv\Scripts\python scripts\delete_participant.py P001`. Delete everything: remove `data/`. Use full-disk encryption on the laptop.

## Content ceiling (as implemented)
Permitted: compliments; flirtatious or romantic warmth of the kind found on mainstream messaging/dating apps; personal and emotional questions; casual invitations (coffee, meeting up), questions about clothes, lifestyle, where they live or work in general terms; suggesting to move to another app; secrecy requests, guilt-tripping, and an insistent, pushy register (a persona trait, driven by the register scalar).
Prohibited at all times (enforced in `backend/filters.py`, `CEILING_ENFORCED` is on): sexual acts, anatomy or explicit language; sexual role-play; requesting/offering sexual or nude images or video; minors or youthfulness; threats, blackmail or coercion; asking for money; asking for an exact home address, phone number, email or full name; encouraging self-harm.
> **Note for the thesis appendix:** this is slightly wider than the written ceiling the ethics board first provided (which also excluded meeting proposals, pressure/secrecy and workplace/location questions). The relaxation was made on the researcher's statement that the board agreed. Get the board's updated wording in writing and keep it with the thesis (see `docs/ETHICS_NOTES.md`, D-031).
The persona never ends a chat itself: if the model produces something blocked, it retries with a targeted correction, then writes an in-character deflection. Only these end or pause a chat: the participant (Stop / `STOP`), the 45-minute limit (a reply already being written is finished first), a user who says they are under 18 (hard line: the persona never talks on with a self-declared minor), and distress words, which pause the chat with support lines and let the participant continue or end it.

## Safeguards (summary, see docs/SECURITY.md)
Stop button + whole-message `STOP`; server-side 45-min clock with sweeper; age gate and adult-only personas (19+); output filter; under-18 statements end the chat and distress words pause it, both with support lines; helplines with a verification date (app refuses to run if older than 60 days); data stored locally; with a cloud provider the chat text goes to the model provider (stated on the consent page).

- Check `config/app.yaml` `study:` details; test one full session yourself; keep a researcher present.

## Tests
